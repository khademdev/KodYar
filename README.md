# MyAI — دستیار هوشمند کدنویسی ایجنتی (اپلیکیشن دسکتاپ Native)

MyAI یک اپلیکیشن دسکتاپ **کاملاً native** برای گفتگو با مدل‌های هوش مصنوعی و **کار ایجنتی روی پروژه‌ها**
است؛ ساخته‌شده با **Wails v2 (Go + WebView سیستمی)** — بدون Electron، بدون وابستگی به مرورگر خارجی
و با مصرف حداقلی منابع. رابط کاربری **۱۰۰٪ فارسی و راست‌به‌چپ** است و ظاهر آن مطابق mockupهای طراحی
(تم تاریک مدرن با اکسنت بنفش) پیاده‌سازی شده است.

## تازه‌های نسخه‌ی 1.9.0 — تشخیص خودکار مدل‌ها

**دیگر لازم نیست نام مدل‌ها را از سایت سرویس‌دهنده کپی کنید — MyAI خودش می‌پرسد:**

- **دکمه‌ی ✨ «تشخیص خودکار» در مودال Provider** — با Base URL و کلید API، فهرست مدل‌های در دسترس مستقیم از خودِ سرویس‌دهنده گرفته می‌شود و در فیلد مدل‌ها پر می‌شود؛ مدل‌های دستیِ قبلی حذف نمی‌شوند (ادغام بدون تکرار)
- **سه مسیر کشف** — مسیر استاندارد سازگار با OpenAI یعنی `GET {base}/models` (OpenAI، OpenRouter، Groq، DeepSeek، Mistral، LM Studio، Ollama، vLLM، LiteLLM و…)، مسیر بومی Google AI Studio (`/v1beta/models`؛ فقط مدل‌های چت‌ capable با پنجره‌ی کانتکست واقعی) و پایه‌ی سازگار OpenAI گوگل (`…/v1beta/openai`)
- **فقط کلید هم کافی است** — اگر Base URL خالی باشد از پیشوند کلید حدس زده می‌شود: `AIza…` → Google AI Studio، `sk-or-…` → OpenRouter، `gsk_…` → Groq؛ برای «sk-» عمومی (مبهم) آدرس پرسیده می‌شود. برای Provider موجود، کلید ذخیره‌شده هم استفاده می‌شود
- **مرتب‌سازی هوشمند** — مدل‌های چت‌مانند اول، embedding/TTS/تصویر آخر (هیچ‌چیز حذف نمی‌شود)؛ تکراری‌ها پاک و نام نمایشی/پنجره‌ی کانتکست سرویس‌دهنده استفاده می‌شود
- **مرزهای امنیتی** — کلید هرگز در خطا/لاگ نمی‌آید؛ سقف پاسخ ۴MB؛ فقط http/https؛ timeout سخت ۲۰ ثانیه؛ پیام خطای فارسیِ روشن برای 401/403/404/429/5xx و پاسخ غیرJSON

## تازه‌های نسخه‌ی 1.8.1 — پایداری: نه کرش، نه هنگ، نه خراب‌شدن داده

**این نسخه هیچ قابلیت تازه‌ای ندارد — فقط نقص‌های پایداری حذف شده و هر کدام با تست اثبات شده است:**

- **برنامه از panic نمی‌میرد** — هر خطای داخلی در هر گوروتینی (استریم، ابزارهای موازی، MCP، اجرای دستور، چک‌پوینت) مهار و در «لاگ خطاها» ثبت می‌شود؛ گفتگو با اعلان فارسی تمام می‌شود و UI هرگز در «در حال تولید» گیر نمی‌کند؛ جفت‌بندی ابزارها سالم می‌ماند
- **پایان «در حال فکر کردن» بی‌نهایت** — اگر سرویس‌دهنده/پروکسی وسط پاسخ، داده نفرستد و اتصال را هم نبندد، نگهبان سکون (۱۲۰ ثانیه، تنظیم پنهان) آن را تمام می‌کند: پاسخ نیمه‌کاره ذخیره می‌شود، علت با پیام فارسی گفته می‌شود و «ادامه» کار می‌کند؛ تلاش مجدد خودکار فقط پیش از اولین خروجی است تا اثر جانبی دوبله رخ ندهد
- **گفتگوی خراب، نجات پیدا می‌کند** — فایل گفتگو/`changes.json` پیش از هر نوشتن یک نسخه‌ی `.bak` دارد؛ در خرابی، پیام‌های سالم تا نقطه‌ی خراب نجات داده می‌شوند و اعلان «گفتگو آسیب دیده بود؛ n پیام بازیابی شد.» می‌آید (نسخه‌ی آسیب‌دیده با نام `.corrupt-…` نگه‌داری می‌شود؛ هیچ‌چیز خودکار حذف نمی‌شود)
- **نوشتن روی فایلِ بازِ برنامه‌ی دیگر** — روی ویندوز (آنتی‌ویروس/ایندکسر/ویرایشگر) تا ۶ تلاش با backoff تکرار می‌شود و در شکست، خطای روشن با نام فایل می‌آید
- **بازگردانی چک‌پوینت واقعاً بایت‌به‌بایت** — `core.autocrlf` سراسری، `.gitattributes` و فیلترهای LFS دیگر خط پایان/محتوای فایل‌ها را در snapshot و بازگردانی تغییر نمی‌دهند؛ پوشه‌ای که به symlink/junction تبدیل شده باشد رد و گزارش می‌شود؛ مقایسه/نوشتن جریانی است و حافظه با فایل بزرگ تورم نمی‌کند؛ فرایند gitِ هنگ‌کرده با کل درختش کشته می‌شود
- **اثبات بار** — ۹ هدف fuzz با کورپوس ثابت، حلقه‌ی soak با سنجش نشت گوروتین/حافظه/هندل، ۹ سناریوی تزریق خرابی (۴۲۹/۵۰۳، SSE خراب، panic ابزار، دیسک پر، سکون استریم، کرش/هنگ MCP، غایب/هنگ بودن git) و ممیزی خودکار ترتیب قفل‌ها

**دقت ایجنت، بازگشت‌پذیری کامل (حتی برای دستورها)، سخت‌سازی امنیتی و سناریوهای اثبات سرتاسری:**

- **تذکر راستی‌آزمایی** — تغییر فایل بدون تست/ساخت موفق، یک راهنمای یک‌باره به حلقه‌ی ایجنت می‌افزاید تا دستور build/test را اجرا کند یا صادقانه بگوید نتوانسته تأیید کند
- **سقف توکن هر نوبت (واقعاً اعمال می‌شود)** — هشدار در ۸۰٪، توقف مودبانه بعد از دور جاری با حفظ امکان «ادامه»، شمارش مصرف زیرایجنت‌ها هم داخل سقف
- **نقطه‌ی بازگشت کل پروژه** — کارت خلاصه‌ی نوبت حالا «بازگردانی کل پروژه به قبل از این نوبت» دارد که با snapshot مخفیِ git حتی اثر جانبی دستورها را هم برمی‌گرداند؛ بازگردانی هیچ‌چیز حذف نمی‌کند (سبد زباله‌ی قابل‌بازگشت)
- **حالت ویرایش و مسیرهای محافظت‌شده** — «ویرایش خودکار» یا «بازبینی هر تغییر»؛ مسیرهای حساس (.env، فایل‌های تعریف ساخت، .git تودرتو حتی در submodule) حتی در حالت خودکار تأیید می‌خواهند
- **دروازه‌ی دستورات شله‌آگاه** — تجزیه‌گر واقعی CMD/POSIX + لیست‌سفید ساختاری: تلاش‌های معروف دورزدن (`&`، تغییرمسیر، `-exec`، `--output`، `^`، `%VAR%`) پرسش یا رد می‌شوند، هرگز اجرا
- **web_fetch فقط برای هر دامنه** — «همیشه اجازه» برای کل ابزار حذف شد؛ «همیشه برای همین دامنه» جایگزین است و قاعده‌های قدیمیِ سراسری به حالت پرسش برمی‌گردند
- **گسترش واقعیت‌های پروژه و کارها** — نوع پروژه و دستورهای راستی‌آزمایی پیشنهادی به پرامپت اضافه می‌شود و فهرست کارها از فشرده‌سازی کانتکست جان سالم به در می‌برد

## تازه‌های نسخه‌ی 1.7.1 — بازبینی کامل و سخت‌سازی

**بازبینی مستقل کامل پروژه (بک‌اند + فرانت‌اند + مصرف منابع + قابلیت اطمینان) با ۱۶ باگ رفع‌شده و ۹ تست رگرسیون جدید (مجموع ۳۶۹):**

- **رفع بحرانی مودال اجازه** — مودال تأیید دسترسی (اجرای دستور، خواندن فایل حساس، دریافت وب، ابزار MCP) به‌دلیل نبود کلاس `open` نامرئی و غیرقابل‌کلیک بود و همه‌ی درخواست‌ها پس از ۳ دقیقه خودکار «رد» می‌شدند؛ رفع و تست رگرسیون شد
- **MCP مقاوم‌تر** — چرخه‌ی بهبود بعد از کرش سرور که عملاً مرده بود فعال شد (حذف کلاینت مرده + backoff + راه‌اندازی مجدد خودکار)؛ نوشتن روی stdin سرورِ هنگ‌شده دیگر کل نوبت ایجنت را قفل نمی‌کند (نگهبان ۱۰ ثانیه‌ای + کشتن درخت فرایند)؛ آخرین پاسخ‌های سرورِ در حال خروج دیگر گم نمی‌شوند
- **قابلیت اطمینان** — فرمان‌های git با فرزندِ نگاه‌دارنده‌ی لوله دیگر بی‌نهایت بلاک نمی‌شوند (WaitDelay)؛ مودال خواندن فایل حساس با بستن برنامه فوراً لغو می‌شود؛ فایل قوانین عظیم زیر قفل کران‌دار خوانده می‌شود؛ دو رویداد از زیر قفل خارج شدند؛ shutdown منتظر پایان ذخیره‌ی آخرین نوبت می‌ماند
- **امنیت مرز داده** — فایل settings.json هم‌رسانی‌شده یا فایل گفتگوی کاشته‌شده دیگر نمی‌تواند اسکریپت به WebView تزریق کند: شناسه/رنگ Provider در بارگذاری پاک‌سازی و در ذخیره رد می‌شود و ایندکس گفتگو فقط شناسه‌های الگو‌دار می‌پذیرد
- **رفع باگ‌های فرانت‌اند** — پنل «کارهای ایجنت» هنگام تعویض گفتگو کهنه می‌ماند؛ ویرایشگر MCP بعد از ذخیره پیکربندی قدیمی را نشان می‌داد و ذخیره‌ی دوباره ویرایش را برمی‌گرداند؛ ذخیره‌ی نمونه‌ی نمایشی خالی دیگر تنظیم واقعی نمی‌نویسد

## تازه‌های نسخه‌ی 1.7.0

**چک‌لیست زنده‌ی کارهای ایجنت، ویرایش چندگانه‌ی اتمیک، glob بر اساس زمان، دسترسی وب امن، پشتیبانی MCP و CI:**

- **چک‌لیست کارهای ایجنت (todo_write)** — ایجنت برای کارهای چندمرحله‌ای فهرست کارهایش را با ابزار `todo_write` صریح نگه می‌دارد و شما آن را به‌صورت زنده در پنل «کارهای ایجنت» بالای جعبه‌ی پیام می‌بینید (در انتظار / در حال انجام / انجام شد + پیشرفت «۲ از ۵» با ارقام فارسی)؛ فهرست با گفتگو ذخیره می‌شود، در شاخه‌گیری کپی می‌شود و با باز کردن دوباره‌ی گفتگو برمی‌گردد
- **ویرایش چندگانه‌ی اتمیک (edit_file با edits)** — چند تغییر در یک فایل با آرایه‌ی `edits` (تا ۲۰ مورد) به‌ترتیب و «همه یا هیچ» اعمال می‌شود: اگر هر ویرایشی شکست بخورد هیچ‌چیز نوشته نمی‌شود و خطا می‌گوید ویرایش شمارهٔ چند و به چه علتی ناموفق بوده؛ یک بکاپ، یک Diff و یک تأیید برای کل مجموعه — شکل تک‌ویرایش مثل قبل کار می‌کند
- **glob بر اساس زمان تغییر** — نتایج `glob` جدیدترین فایل اول مرتب می‌شوند (تساوی با مسیر)؛ تا ۲۰٫۰۰۰ کاندید حین پیمایش جمع و پس از مرتب‌سازی ۵۰۰ نتیجه‌ی اول برگردانده می‌شود؛ فیلترهای gitignore و لغو با Stop مثل قبل
- **دریافت از وب با محافظت SSRF (web_fetch)** — ایجنت می‌تواند مستندات/صفحات خطا را با تأیید شما بخواند: فقط http/https و محتوای متنی؛ گارد اتصال IPِ «واقعاً resolve‌شده» را بازرسی می‌کند (حلقه‌ی محلی، محدوده‌های خصوصی/لینک-محلی شامل metadata ابر، CGNAT و…) و روی هر پرش redirect هم اعمال می‌شود؛ صفحات windows-1256/ISO-8859-6 درست decode می‌شوند و خروجی در پوشش `untrusted` می‌آید که محتوای آن فقط «داده» است، نه دستور
- **سرورهای MCP (ابزارهای خارجی)** — سرورهای MCP استاندارد (stdio) را از تب جدید «MCP» تنظیمات با یک ویرایشگر JSON فارسی اضافه کنید؛ شروع تنبل و موازی، restart با backoff، کشتن کامل درخت فرایند هنگام بستن، متغیرهای محیطی رمزنگاری‌شده در settings.json و فقط ماسک‌شده در UI؛ ابزارهای هر سرور با پیشوند `mcp_` به مدل معرفی می‌شوند و هر فراخوانی با تأیید شما اجرا می‌شود؛ خروجی در پوشش `untrusted` با کران حجم
- **پرامپت آگاه از پلتفرم و CI** — پرامپت ایجنت حالا سیستم‌عامل و shell واقعی (CMD در ویندوز، sh در لینوکس/مک) را با راهنمای مناسب همان shell می‌گوید؛ بستن برنامه تأییدهای در انتظار را هم قطع می‌کند؛ گردش‌کار CI گیت‌هاب (تست windows با race detector + کامپایل لینوکس با GTK/WebKit + بیلد Wails) اضافه شد
- تست‌های جدید در همه‌ی بخش‌ها (از جمله رگرسیون‌های فارسی/ZWNJ، رقابت داده‌ای با race detector، کشتن درخت فرایند و سرور MCP ساختگی) — کل مجموعه با `go vet` و race detector سبز است


**ابزار `task` — زیرایجنت فقط‌خواندنی با کانتکست تازه:**

- **زیرایجنت برای زیرکارهای اکتشافی** — ایجنت اصلی حالا می‌تواند یک زیرکارِ خودکفای
  جستجو/تحلیل («همه‌ی جاهایی که X پیکربندی شده را پیدا کن و جریانش را خلاصه کن») را با ابزار
  `task` به یک زیرایجنت با **کانتکست کاملاً تازه** بسپارد؛ زیرایجنت با ابزارهای فقط‌خواندنی
  (`list_dir`، `read_file`، `search_files`، `glob` و ابزارهای `git_*`) کار می‌کند و
  **گزارش ساختارمند** (یافته‌ها + نکته‌ها) به‌همراه آمار (تعداد دور، توکن، زمان) به ایجنت اصلی
  برمی‌گرداند — کانتکست مکالمه‌ی اصلی کوچک می‌ماند
- **ایزوله و امن از اساس** — زیرایجنت فقط همان ۸ ابزار فقط‌خواندنی را می‌بیند: تغییر فایل،
  اجرای دستور، ابزارهای سفارشی و حتی `task` تودرتو از ابتدا در دسترسش نیست (عمق = ۱)؛
  **فایل‌های حساس (مثل `.env`)** داخل زیرایجنت بدون بازشدن هیچ مودالی رد می‌شوند و
  مسیرها مثل همیشه از `resolveWorkspacePath` می‌گذرند
- **مصرف کنترل‌شده** — سقف دورهای ابزار زیرایجنت با تنظیم جدید «حداکثر مراحل زیرایجنت»
  (پیش‌فرض ۸، محدوده‌ی ۳ تا ۵۰؛ تب «مدل و رفتار») + سقف مطلق ۵ دقیقه؛ حذف هر دو با Stop کاربر؛
  خروجی نهایی کران‌دار (۸K کاراکتر head+tail) و نتایج ابزارها مثل قبل ۱۶K
- **همان موتور اثبات‌شده، بدون کپی‌کاری** — حلقه‌ی headless زیرایجنت عیناً از تلاش مجدد هوشمند
  ، بودجه/فشرده‌سازی/بازیابی سرریز کانتکست، اعتبارسنجی آرگومان‌ها 
  و محافظ حلقه‌ی تکرار استفاده می‌کند؛ هیچ رویداد UI نمی‌فرستد و چیزی روی دیسک نمی‌نویسد
- **اجازه‌ی صریح هر واگذاری** — ابزار `task` به‌طور پیش‌فرض «بپرس» است و مودال اجازه، خلاصه‌ی
  مأموریت را هم نشان می‌دهد («اجازه‌ی سپردن این زیرکار به زیرایجنتِ فقط‌خواندنی؟»)؛ با
  «همیشه اجازه بده» یا تب «دسترسی‌ها» مثل بقیه‌ی ابزارها قابل آزادکردن است؛ رد شدن، خطای
  انگلیسیِ راهنما به مدل برمی‌گردد تا خودش ادامه دهد
- خطاهای ابزار داخل زیرایجنت به خودِ مدل برمی‌گردند تا مسیر دیگر امتحان کند؛ خطاهای موقت
  سرویس‌دهنده مثل قبل با backoff دوباره تلاش می‌شوند و در «لاگ خطاها» ردیابی می‌شوند
- تست‌های جدید: تعریف/اعتبارسنجی/دسترسی ابزار، allowlist و عمق ۱، رد فایل حساس بدون مودال،
  حلقه‌ی چندمرحله‌ای روی سرور SSE آزمایشی، سقف دورها، محافظ تکرار، لغو والد، تنظیمات
  (پیش‌فرض/clamp/SettingsView) و جریان کامل والد→task→گزارش (اجازه و رد) — مجموعه‌ی تست به
  **۲۶۲ تابع در ۳۱ فایل** رسید؛ کل مجموعه با `go vet` و race detector سبز است

  فقط در فاز برقراری اتصال (قبل از شروع استریم) با backoff نمایی، full jitter و احترام به هدر
  `Retry-After` دوباره تلاش می‌شوند (حداکثر ۴ تلاش)؛ شکست میانه‌ی استریم همچنان پاسخ جزئی را
  ذخیره می‌کند و به کاربر اطلاع می‌دهد
- **بودجه‌ی کانتکست آگاه از توکن** — بودجه = پنجره‌ی کانتکست Provider منهای رزرو خروجی و ۱۰٪
  حاشیه‌ی ایمنی؛ شمارش توکن تاریخچه با کش (هر پیام فقط یک‌بار تخمین زده می‌شود)؛ فشرده‌سازی
  خودکار وقتی تاریخچه به ≥۸۰٪ بودجه برسد (فقط روی کپیِ ارسالی به مدل — فایل گفتگو دست‌نخورده
  می‌ماند) و **بازیابی خودکار از خطای «کانتکست بزرگ‌تر از پنجره»** با فشرده‌سازی تهاجمی‌تر و یک
  تلاش مجدد (بدون مصرف دور اضافه از سقف ایجنت)
- **کالیبراسیون تخمین توکن** — نسبت `prompt_tokens` واقعیِ هر پاسخ برای کالیبره‌کردن بودجه‌ی همان
  گفتگو استفاده می‌شود تا تخمین‌ها در طول مکالمه به واقعیت نزدیک بمانند
- **اجرای موازی ابزارهای فقط‌خواندنی** — فراخوانی‌های پشت‌سرهمِ خواندنی (`list_dir`، `read_file`،
  `search_files`، `glob` و ابزارهای `git_*`) در یک پیام دستیار با سقف ۴ worker هم‌زمان اجرا می‌شوند؛
  ابزارهای تغییردهنده همچنان ترتیبی اجرا می‌شوند و مثل مانع، مرز دسته‌ی موازی بعدی‌اند
- **ابزار glob (جدید)** — یافتن فایل‌ها با الگوی glob فقط بر اساس نام (محتوای فایل هرگز خوانده
  نمی‌شود): `**` هر عمق را تطبیق می‌دهد (مثل `**/*.go`)، الگوی بدون `/` با نام فایل در هر عمق و الگوی
  دارای `/` لنگرشده به ریشه‌ی جستجوست؛ سقف ۳۰۰ نتیجه، احترام کامل به `.gitignore` و پوشه‌های
  build/cache
- **تطبیق‌گر مقاوم edit_file** — اگر تطبیق دقیق `old_string` پیدا نشد، به‌ترتیب با نرمال‌سازی
  CRLF/LF، تحمل فاصله‌ی انتهایی خطوط و تحمل تورفتگی (فقط وقتی تطبیق یکتا باشد — حتی با
  `replace_all`) دوباره تلاش می‌شود؛ BOM و سبک خطِ جدید فایل بایت‌به‌بایت حفظ و همه‌ی رخدادها
  در یک ساخت درون‌حافظه‌ای و یک نوشتن اتمیک اعمال می‌شوند (یا همه، یا هیچ)؛ پیام نتیجه گزارش
  می‌کند کدام استراتژی تطبیق یافته است
- **فایل‌های قاعده‌ی استاندارد‌تر** — قوانین پروژه علاوه بر `.myai/rules.md`، `.cursorrules` و
  `.myairules` حالا از `AGENTS.md` و `CLAUDE.md` هم خوانده می‌شود (اولین تطبیق برنده) و محتوای
  تغییرنکرده با کش (مسیر + حجم + mtime) نگه داشته می‌شود تا در هر نوبت دوباره خوانده نشود
- فراخوانی‌های نامعتبر ابزار به‌جای شکست کل نوبت، نتیجه‌ی خطای راهنما به مدل برمی‌گردانند تا خودش
  اصلاح کند؛ خروجی ابزارها و رویدادهای استریم همه کران‌دار و امن باقی می‌مانند
- تست‌های جدید: تلاش مجدد، بودجه/فشرده‌سازی/سرریز کانتکست، کالیبراسیون، اجرای موازی، glob،
  تطبیق‌گر edit و فایل‌های قاعده — مجموعه‌ی تست به **۲۴۵ تابع در ۳۰ فایل** رسید؛ کل مجموعه با
  `go vet` و race detector سبز است

## تازه‌های نسخه‌ی 1.4.0

**سخت‌سازی production: سیستم دسترسی کامل، اجرای امن دستورات، رمزنگاری کلیدها و نوشتن اتمیک:**

- **سیستم دسترسی (Permissions)** — هر ابزار ایجنت به یکی از `allow | ask | deny` نگاشت می‌شود و
  `run_command` علاوه بر آن قاعده‌های الگویی مرتب دارد (اولین تطبیق برنده، مثل `cargo build*`).
  ترتیب ارزیابی: **لیست سیاه سخت** (دستورات تخریب‌گر مثل `rm -rf /`، `mkfs`، fork bomb — هرگز
  حتی با تأیید کاربر اجرا نمی‌شوند) → **قاعده‌های شما** → **الگوهای پرریسک** (مثل
  `git push --force` و `git reset --hard` — تأیید اضافه) → لیست‌سفید امن → پیش‌فرض **بپرس**.
  دستورات مرکب (`&&`، `||`، `;`، `|`، `$()`، backtick، خط جدید و payload مفسرها مثل
  `bash -c '…'`) به اجزا تقسیم و هر جزء جداگانه ارزیابی می‌شود؛ سخت‌گیرترین تصمیم برنده است
- **مودال دسترسی یکپارچه** — درخواست‌های «اجازه اجرای دستور»، «خواندن فایل حساس» (مثل `.env`)
  و «اجرای ابزار» همه از یک مودال با گزینه‌ی **«همیشه اجازه بده»** می‌گذرند؛ انتخاب always یک
  قاعده‌ی ماندگار می‌سازد
- **تب تنظیمات «دسترسی‌ها» (جدید)** — فهرست کامل قاعده‌های «همیشه اجازه بده» با دکمه‌ی حذف
  (ابطال اجازه‌های داده‌شده)، override هر ابزار با کنترل چهارحالته (پیش‌فرض/اجازه/بپرس/رد)،
  نمایش فایل‌های حساس و **بازنشانی کامل** دسترسی‌ها با تأیید دو مرحله‌ای
- **اجرای امن و کامل دستورات** — همه‌ی مسیرها (`run_command` ایجنت، ترمینال UI و ابزارهای
  سفارشی) از یک دروازه‌ی واحد می‌گذرند. کشتن درخت فرایند: **Job Object** در ویندوز و
  **Setpgid + SIGTERM→SIGKILL** در یونیکس؛ مهلت ۶۰ ثانیه (سقف ۳۰۰)؛ خروجی کران‌دار
  (head+tail با نشانگر truncation) و رویدادهای تدریجی خروجی (حداکثر ۱۰ رویداد در ثانیه)
- **رمزنگاری کلیدهای API** — AES-GCM با کلید اصلی در **keyring سیستم‌عامل** (فرمت `v2:`؛
  مهاجرت خودکار از فرمت قدیمی و fallback امن اگر keyring در دسترس نباشد)؛ همه‌ی فایل‌های
  داده (settings، گفتگوها، changes) با **نوشتن اتمیک** (فایل موقت هم‌پوشه → fsync → rename)
  ذخیره می‌شوند تا پس از کرش نیمه‌نوشته نمانند
- **پایبندی به `.gitignore`** — `search_files` و `list_dir` قواعد `.gitignore` پروژه (شامل
  فایل‌های تودرتو و الگوهای `!negate`/`**`) را رعایت می‌کنند؛ سقف‌های حافظه هم برای فایل‌های
  بزرگ gitignore
- خروجی ابزارها bounded (سقف ۱۶K کاراکتر با head+tail)، خواندن فایل خط‌به‌خط با `bufio`
  (بدون بارگذاری کل فایل در حافظه) و شمارش توکن افزایشی فقط برای پیام‌های جدید
- تست‌های جدید: تطبیق glob، تجزیه دستور مرکب و تلاش‌های دورزدن، پایداری/حذف قواعد، مهاجرت
  تنظیمات قدیمی، رمزنگاری v2 و fallback، gitignore، کشتن درخت فرایند، نشت گوروتین و
  مدیریت هم‌زمان دسترسی‌ها — کل مجموعه با race detector سبز

  بدون ابزار تلاش می‌شود و به کاربر اطلاع داده می‌شود

- **صفحه‌ی چت با حالت خالی زیبا** — آیکون تراشه‌ی AI درخشان، پیام خوش‌آمد، چیپ‌های پیشنهاد سریع
  (نوشتن قطعه کد، بررسی پروژه با ایجنت، ایده‌پردازی، اشکال‌زدایی، بازبینی امنیت کد)
- **مکالمه‌ی کامل** — حباب کاربر سمت راست (تیره‌تر)، پاسخ AI سمت چپ با رندر کامل **Markdown**،
  جدول، نقل‌قول و **بلوک کد با شماره‌ی خط، هایلایت سینتکس و دکمه‌ی کپی**
- **پاسخ استریمی** — نشانگر «در حال فکر کردن…»، کرسر تایپ زنده، دکمه‌ی «توقف» (هم در composer و
  هم کنار پاسخ) + «تولید دوباره» واقعی روی آخرین پاسخ
- **سایدبار راست** — دکمه‌ی «گفتگوی تازه»، جستجوی گفتگوها، لیست گفتگوها با تاریخ نسبی فارسی
  («امروز 10:42»، «۲ روز پیش»)، نشان «جدید»، حذف تکی و «حذف همه» با تأیید
- **مودال تنظیمات با ۳ تب**:
  - **اتصال** — انتخاب Provider (با آیکون)، مدل (با پیشنهاد خودکار)، کلید API با نمایش/مخفی،
    تست اتصال و ذخیره‌ی رمزنگاری‌شده‌ی کلید (AES-GCM)
  - **Provider ها** — افزودن/ویرایش/حذف سرویس‌دهنده‌های سازگار با API نوع OpenAI؛ فرم Provider همه‌چیز
    را همان اول می‌پرسد: **نام، Base URL، مدل‌ها، پنجره‌ی کانتکست و کلید API** — بعد از ذخیره،
    Provider تازه بلافاصله فعال می‌شود و نیازی به مراجعه‌ی جداگانه برای کلید نیست
    (بدون Provider پیش‌فرض — کاربر خودش تعریف می‌کند)
  - **پوشه‌ی کاری (مسیر پروژه)** — **تایپ مستقیم مسیر** (مثلاً `C:\Projects\MyApp`) یا انتخاب با
    دیالوگ سیستم‌عامل؛ اگر مسیر وجود نداشته باشد هنگام ذخیره **به‌صورت خودکار ساخته می‌شود** و
    خطاها همراه با علت واقعی نمایش داده می‌شوند + سوییچ «اجازه اجرای دستور»
- **سوییچ‌های «حالت ایجنت» و «اجرا دستور» در سایدبار** — هماهنگ با تنظیمات؛ اجرای دستور فقط در
  پوشه‌ی کاری و فقط با اجازه انجام می‌شود
- **سنجه‌ی مصرف توکن** — نوار پیشرفت با رنگ هوشمند (بنفش → کهربایی → قرمز)، درصد فارسی و
  نمودار خطی کوچک (sparkline) از آخرین پاسخ‌ها
- **انتخابگر مدل و محیط** — پاپ‌اور گروه‌بندی‌شده بر اساس Provider در نوار بالا + انتخابگر «محیط»
  (General / توسعه‌دهنده / آموزش) که پرامپت سیستم را عوض می‌کند
- **مدیریت BiDi** — کدها، مسیر فایل‌ها و URLها همیشه با `unicode-bidi: isolate` و جهت LTR
  نمایش داده می‌شوند و متن فارسی راست‌چین می‌ماند

## مدل امنیتی / Security model

**فارسی — صادقانه و بدون اغراق:**

- **ابزارهای فایل فقط داخل پوشه‌ی کاری** — همه‌ی مسیرهای داده‌شده به ابزارها از ریشه‌ی پروژه حل می‌شوند؛ خروج با `..` یا مسیر مطلق/فرار مسدود است. فایل‌های حساس (`.env*`، `*.pem` و…) و مسیرهای محافظت‌شده (.git حتی تودرتو، فایل‌های تعریف ساخت مثل `package.json`) حتی در «ویرایش خودکار» مودال تأیید می‌گیرند.
- **دستورها گیت‌دار هستند اما sandbox نیستند** — اجرای دستور از سه لایه می‌گذرد: تجزیه‌گر شله‌آگاه (عدم‌قطعیت = پرسش)، لیست‌سفید ساختاری (git/go/npm با پرچم صریح) و بررسی توکن حساس/مسیر محافظت‌شده. اما دستورِ تأییدشده در نهایت با دسترسی کامل کاربر شما اجرا می‌شود — MyAI ماشین مجازی/کانتینر نیست و جایگزین سندباکس نیست.
- **دستورهای تست/ساختِ خودکارِ اجازه‌ی بدون پرسش کد اجرا می‌کنند** — `go test`، `npm test` و مانند آن‌ها بدون مودال اجرا می‌شوند چون بی‌خطر به نظر می‌رسند؛ اما آن‌ها همان کدی را اجرا می‌کنند که ایجنت چند لحظه قبل نوشته است. **شبکه‌ی ایمنی واقعی، بازبینی پایان نوبت و نقطه‌ی بازگشت است**: کارت «خلاصه‌ی واقعی این نوبت» ببینید، «برگرداندن همه‌ی تغییرات این نوبت» و «بازگردانی کل پروژه به قبل از این نوبت» در دسترس‌اند و بازگردانی هیچ‌چیز حذف نمی‌کند (سبد زباله).
- **حالت‌های ویرایش** — «بازبینی هر تغییر» مودال Diff برای هر نوشتن می‌دهد؛ «ویرایش خودکار» فقط مسیرهای محافظت‌شده و حذف سنگین را می‌پرسد و بقیه را در خلاصه‌ی نوبت گزارش می‌کند.
- **نظم راستی‌آزمایی و سقف توکن** — ایجنت بعد از تغییر فایل بدون تست/ساختِ موفق یک تذکر یک‌باره می‌گیرد؛ «سقف توکن هر نوبت» مصرف همه‌ی دورها + زیرایجنت‌ها را می‌سنجد و نوبت را مودبانه متوقف می‌کند.
- **اعتماد به محتوای بیرونی** — خروجی `web_fetch` و ابزارهای MCP در پوشش `untrusted` به مدل می‌رسد (فقط داده، نه دستور)؛ گارد SSRF اتصال را در هر پرش بازرسی می‌کند؛ اجازه‌ی web_fetch فقط برای هر دامنه ذخیره می‌شود (هرگز برای کل ابزار). سرورهای MCP فرایند قابل‌اعتمادِ شما هستند اما با محیط حداقلی بالا می‌آیند (بدون کلیدهای API برنامه) و هر فراخوانی ابزارشان مودال اجازه دارد.
- **داده‌ها روی دستگاه شما** — کلید API با AES-GCM و کلید میزبان در Keyring سیستم‌عامل رمز می‌شود؛ محیطی متغیرهای MCP رمزنگاری‌شده ذخیره و در UI فقط ماسک می‌شوند؛ هیچ چیزی جز آدرس Provider به بیرون رفت نمی‌کند (و آن هم فقط به سرویس‌دهنده‌ی خودتان).
- **گردش‌کار پیشنهادی** — روی یک شاخه‌ی git کار کنید، حالت ویرایش را آگاهانه انتخاب کنید، در پایان هر نوبت کارت خلاصه را بخوانید و در صورت شک، اول «برگرداندن نوبت» و بعد «بازگردانی کل پروژه» را امتحان کنید.
- **پایداری (1.8.1)** — خطای داخلی برنامه را نمی‌کشد (مهار panic در همه‌ی گوروتین‌ها و متدهای بایند‌شده)، سکون سرویس‌دهنده با نگهبان ۱۲۰ ثانیه‌ای تمام می‌شود، فایل گفتگو/`changes.json` با `.bak` و نجات پیام‌های سالم بازیابی می‌شوند و بازگردانی چک‌پوینت با `EvalSymlinks`/رد reparse از نوشتن بیرونِ پروژه جلوگیری می‌کند. این‌ها جایگزین سندباکس **نیستند** — بند دوم بالا همچنان برقرار است.

**English — stated honestly, without overstatement:**

- **File tools are confined to the workspace.** Every model-supplied path is resolved against the workspace root; `..`, absolute and escape paths are rejected. Sensitive files (`.env*`, `*.pem`, …) and protected paths (`.git` including nested submodule ones, build-definition files like `package.json`) always ask, even in the "auto" edit mode.
- **Commands are gated, but not sandboxed.** Command execution passes a shell-aware parser (uncertainty → ask), a structural allow-list (git/go/npm with explicit flags) and sensitive-token/protected-path checks — but an approved command ultimately runs with **your** full user privileges. MyAI is not a VM/container and does not replace a sandbox.
- **Auto-allowed test/build commands execute code the agent may have just written.** `go test`, `npm test` and similar are auto-allowed because they look harmless — yet they run whatever the agent just wrote. The real safety net is the end-of-turn review and project checkpoints: read the "real turn summary" card, and both "revert this turn" and "restore the whole project" are one click away; restore never deletes (it rescues into a trash folder).
- **Edit modes** — "review each change" shows a diff modal for every write; "auto" only asks for protected paths and heavy deletes and reports everything else in the turn summary.
- **Verification discipline & token cap** — a final answer without a successful build/test since the last file change triggers a one-time verification nudge; «سقف توکن هر نوبت» (max tokens per turn) counts all rounds plus sub-agents and stops the turn gracefully.
- **Untrusted content** — `web_fetch` and MCP results reach the model inside an `untrusted` envelope (data, never instructions); the SSRF guard re-checks every redirect hop; web_fetch permissions are stored **per host** only — never tool-wide. MCP servers are your trusted local processes but run with a minimal environment (never the app's API keys) and every tool call asks.
- **Your data stays on your machine** — API keys are AES-GCM encrypted with an OS-keyring master key; MCP env vars are encrypted and masked in the UI; nothing leaves the device except your own provider requests.
- **Recommended workflow** — work on a git branch, choose the edit mode deliberately, read the turn summary card after every turn, and when in doubt try "revert this turn" first, then "restore the whole project".
- **Stability (1.8.1)** — an internal error no longer kills the app (panic recovery in every goroutine and bound method), a silently stalled provider stream ends after a 120 s idle watchdog, conversation/`changes.json` files get `.bak` + salvage recovery with a Persian notice, and checkpoint restore refuses symlinked/junction parents (real-path resolution) and streams file comparisons so memory stays flat. These are resilience guarantees, **not** a sandbox — the "not sandboxed" bullet above still applies verbatim.

```bash
cd myai

wails dev

wails build
```

## معماری ارتباط فرانت‌اند و بک‌اند

- متدهای `App` (فایل‌های Go) به‌صورت خودکار توسط Wails به `window.go.main.App` بایند می‌شوند
  (`SettingsView`، `SendMessage`، `SaveConnection`، `SaveProvider`، `SelectFolder`، …)
- استریم پاسخ با **رویدادهای Wails** به فرانت‌اند می‌رسد:
  - `chat:start` — شروع پاسخ (همراه گفتگوی تازه‌ساخته‌شده)
  - `chat:delta` — هر تکه‌ی متن
  - `chat:tool` / `chat:tool_result` — شروع/پایان هر فراخوانی ابزار ایجنت
  - `chat:notice` — اطلاعیه‌ها (مثلاً پشتیبانی‌نشدن ابزار توسط مدل)
  - `chat:done` — پایان (با مصرف توکن)
  - `chat:error` — خطا
- هر API سازگار با OpenAI (`/chat/completions`) پشتیبانی می‌شود؛ حالت ایجنت از **فراخوانی تابع
  (Function Calling)** استاندارد OpenAI استفاده می‌کند، پس مدل باید ابزار را پشتیبانی کند
  (gpt-4o، llama-3.3، qwen2.5 و…). در صورت پشتیبانی‌نکردن، برنامه به‌صورت خودکار به چت معمولی برمی‌گردد.
  علاوه بر این، هر سرویسی (OpenRouter، Together، سرویس‌های ایرانی و…) از تب
  «Provider ها» قابل افزودن است.
