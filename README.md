# MyAI — دستیار هوشمند کدنویسی ایجنتی (اپلیکیشن دسکتاپ Native)

MyAI یک اپلیکیشن دسکتاپ **کاملاً native** برای گفتگو با مدل‌های هوش مصنوعی و **کار ایجنتی روی پروژه‌ها**
است؛ ساخته‌شده با **Wails v2 (Go + WebView سیستمی)** — بدون Electron، بدون وابستگی به مرورگر خارجی
و با مصرف حداقلی منابع. رابط کاربری **۱۰۰٪ فارسی و راست‌به‌چپ** است و ظاهر آن مطابق mockupهای طراحی
(تم تاریک مدرن با اکسنت بنفش) پیاده‌سازی شده است.

## تازه‌های نسخه‌ی 1.0 — کپی و پیست با راست‌کلیک در ویندوز

- **راست‌کلیک حالا کار می‌کند** — منوی زمینه‌ی بومی WebView2 در نسخه‌ی production روشن شد: روی متن پاسخ‌ها، خروجی ابزارها، بلوک‌های کد، جعبه‌ی پیام و همه‌ی فیلدهای تنظیمات، گزینه‌های «برش / کپی / چسباندن / انتخاب همه» در دسترس است
- **میان‌برهای همیشگی** — `Ctrl+C` و `Ctrl+V` مثل قبل کار می‌کنند؛ دکمه‌های «کپی» پیام‌ها، بلوک‌های کد و مسیر پروژه هم سر جای خود هستند

## تازه‌های نسخه‌ی 1.0 — بازگشت «پروکسی هوشمند» — خودکار، بدون تنظیم دستی

- **حالت «هوشمند» پیش‌فرض شد** — MyAI خودش پروکسی را پیدا می‌کند: اول پروکسی سیستم ویندوز (رجیستری WinINET — همان تنظیمی که نرم‌افزارهای VPN با گزینه‌ی System Proxy عوض می‌کنند و مرورگرها استفاده می‌کنند)، بعد متغیرهای محیطی HTTP(S)_PROXY، و اگر هیچ‌کدام نباشد اتصال مستقیم
- **اگر پروکسی هنگام اتصال مرده باشد، خودش نجات پیدا می‌کند** — خطای proxyconnect دیگر دیده نمی‌شود: همان درخواست مستقیم ادامه می‌یابد، پروکسی ۵ دقیقه کنار گذاشته می‌شود و اگر روشن شود دوباره خودش استفاده می‌کند؛ رویداد در «لاگ خطاها» ثبت می‌شود
- **تنظیم دستی فقط برای استثنا** — سگمنت پروکسی حالا «هوشمند / خاموش / سفارشی» است؛ «خاموش» و «سفارشی» برای وقتی است که خودتان می‌خواهید. تنظیم قدیمیِ هر کس یک‌بار به «هوشمند» برمی‌گردد و انتخاب صریح بعدی‌اش محترم است؛ قواعد بای‌پس ویندوز (localhost، 127.*، …) هم رعایت می‌شود

## تازه‌های نسخه‌ی 1.0 — پایان «فکر بدون جواب» + مصرف توکن به تفکیک مدل

**دو اصلاح ریشه‌ای در موتور چت/ایجنت:**

- **هیچ نوبتی دیگر بی‌صدا تمام نمی‌شود** — اگر مدل فقط استدلال تولید کند و پاسخ متنی ندهد، اگر خروجی وسط فکر‌کردن به «سقف توکن خروجی» بخورد، یا اگر پاسخ کاملاً خالی بماند، حالا اعلان فارسیِ روشن با راهنمای عملی می‌بینید (قبلاً نوبت با ظاهرِ موفقیت تمام می‌شد و فقط بلوک فکر — یا هیچ‌چیز — نمایش داده می‌شد)
- **مصرف توکن هر مدل جدا حساب می‌شود** — سطل اختصاصی هر مدل (TokensByModel)؛ جابه‌جایی بین مدل‌های یک Provider دیگر اعداد را مخلوط نمی‌کند؛ tooltip ویجت مصرف، «مدل فعال» را جدا از «Provider فعلی» نشان می‌دهد؛ زیرایجنت‌ها هم به سطل همان مدل اضافه می‌شوند

## تازه‌های نسخه‌ی 1.10.0 — رابط کاربری حرفه‌ای‌تر + حذف فلش کنسول

**پنج ایراد UI گزارش‌شده اصلاح شد — هر کدام با بازتولید بصری قبل/بعد اثبات شده:**

- **مودال دسترسی کامل نمایش داده می‌شود** — فوتر شبکه‌ای با دکمه‌های هم‌عرض؛ هیچ دکمه‌ای (در هیچ مودالی) دیگر بریده یا له نمی‌شود
- **پیش‌نمایش تغییرات ایجنت جمع‌وجور** — راهنما یک خط بالای دکمه‌ها، عرض ۶۸۰px، فوتر مرتب
- **جستجوی مدل** — در انتخابگر مدلِ چت‌باکس، از ۳ مدل به بالا یک جعبه‌ی جستجوی چسبان بالای فهرست می‌آید؛ تایپ = فیلتر زنده‌ی نام مدل (گروه‌های بی‌نتیجه پنهان می‌شوند)، Enter اولین نتیجه، Esc بستن؛ با جستجوی بی‌نتیجه پیام «مدلی با این نام پیدا نشد» نشان داده می‌شود
- **تنظیمات دسکتاپی** — نوار کناری عمودی (راست در RTL) با هایلایت آیتم فعال؛ در پنجره‌های باریک رفتار قبلی
- **حذف فلش پنجره‌ی سیاه هنگام ارسال پیام** — فرمان‌های git چک‌پوینت و سرورهای MCP دیگر پنجره‌ی کنسول باز نمی‌کنند (`CREATE_NO_WINDOW` + `-H windowsgui`) و تست نگهبان AST از بازگشت این ایراد جلوگیری می‌کند
- **کشوی تغییرات فایل زیر مودال‌ها رفت** و متن تأییدهای حذف شکستن امن کلمه دارد

## تازه‌های نسخه‌ی 1.9.0 — تشخیص خودکار مدل‌ها

**دیگر لازم نیست نام مدل‌ها را از سایت سرویس‌دهنده کپی کنید — MyAI خودش می‌پرسد:**

- **فرم Provider فقط دو فیلد دارد: نام سرویس و کلید API** — بقیه‌ی تنظیم‌ها (آدرس API، فهرست مدل‌ها و پنجره‌ی کانتکست) خودکار از خودِ سرویس‌دهنده خوانده می‌شود
- **سه مسیر کشف** — مسیر استاندارد سازگار با OpenAI یعنی `GET {base}/models` (OpenAI، OpenRouter، Groq، DeepSeek، Mistral، LM Studio، Ollama، vLLM، LiteLLM و…)، مسیر بومی Google AI Studio (`/v1beta/models`؛ فقط مدل‌های چت‌ capable با پنجره‌ی کانتکست واقعی) و پایه‌ی سازگار OpenAI گوگل (`…/v1beta/openai`)
- **تشخیص سرویس از نام/کلید** — پیشوند یکتای کلید (`AIza…` → Google AI Studio، `sk-or-…` → OpenRouter، `gsk_…` → Groq) و نام آزاد سرویس (مثل «OpenRouter (حساب شخصی)»، «LM Studio من») آدرس پایه را مشخص می‌کند؛ اگر در نام آدرس API هم باشد (مثل «سرور من api.example.com/v1») همان استفاده می‌شود. برای «sk-» عمومی مبهم، نام سرویس را واضح بخواهید
- **مرتب‌سازی هوشمند** — مدل‌های چت‌مانند اول، embedding/TTS/تصویر آخر (هیچ‌چیز حذف نمی‌شود)؛ تکراری‌ها پاک و نام نمایشی/پنجره‌ی کانتکست سرویس‌دهنده استفاده می‌شود
- **مرزهای امنیتی** — کلید هرگز در خطا/لاگ نمی‌آید؛ سقف پاسخ ۴MB؛ فقط http/https؛ timeout سخت ۲۰ ثانیه؛ پیام خطای فارسیِ روشن برای 401/403/404/429/5xx و پاسخ غیرJSON

## تازه‌های نسخه‌ی 1.8.1 — پایداری: نه کرش، نه هنگ، نه خراب‌شدن داده

**این نسخه هیچ قابلیت تازه‌ای ندارد — فقط نقص‌های پایداری حذف شده و هر کدام با تست اثبات شده است:**

- **برنامه از panic نمی‌میرد** — هر خطای داخلی در هر گوروتینی (استریم، ابزارهای موازی، MCP، اجرای دستور، چک‌پوینت) مهار و در «لاگ خطاها» ثبت می‌شود؛ گفتگو با اعلان فارسی تمام می‌شود و UI هرگز در «در حال تولید» گیر نمی‌کند؛ جفت‌بندی ابزارها سالم می‌ماند
- **پایان «در حال فکر کردن» بی‌نهایت** — اگر سرویس‌دهنده/پروکسی وسط پاسخ، داده نفرستد و اتصال را هم نبندد، نگهبان سکون (۱۸۰ ثانیه، قابل تنظیم در تب «مدل و رفتار») آن را تمام می‌کند: پاسخ نیمه‌کاره ذخیره می‌شود، علت با پیام فارسی گفته می‌شود و «ادامه» کار می‌کند؛ تلاش مجدد خودکار فقط پیش از اولین خروجی است تا اثر جانبی دوبله رخ ندهد
- **گفتگوی خراب، نجات پیدا می‌کند** — فایل گفتگو/`changes.json` پیش از هر نوشتن یک نسخه‌ی `.bak` دارد؛ در خرابی، پیام‌های سالم تا نقطه‌ی خراب نجات داده می‌شوند و اعلان «گفتگو آسیب دیده بود؛ n پیام بازیابی شد.» می‌آید (نسخه‌ی آسیب‌دیده با نام `.corrupt-…` نگه‌داری می‌شود؛ هیچ‌چیز خودکار حذف نمی‌شود)
- **نوشتن روی فایلِ بازِ برنامه‌ی دیگر** — روی ویندوز (آنتی‌ویروس/ایندکسر/ویرایشگر) تا ۶ تلاش با backoff تکرار می‌شود و در شکست، خطای روشن با نام فایل می‌آید
- **بازگردانی چک‌پوینت واقعاً بایت‌به‌بایت** — `core.autocrlf` سراسری، `.gitattributes` و فیلترهای LFS دیگر خط پایان/محتوای فایل‌ها را در snapshot و بازگردانی تغییر نمی‌دهند؛ پوشه‌ای که به symlink/junction تبدیل شده باشد رد و گزارش می‌شود؛ مقایسه/نوشتن جریانی است و حافظه با فایل بزرگ تورم نمی‌کند؛ فرایند gitِ هنگ‌کرده با کل درختش کشته می‌شود
- **اثبات بار** — ۹ هدف fuzz با کورپوس ثابت، حلقه‌ی soak با سنجش نشت گوروتین/حافظه/هندل، ۹ سناریوی تزریق خرابی (۴۲۹/۵۰۳، SSE خراب، panic ابزار، دیسک پر، سکون استریم، کرش/هنگ MCP، غایب/هنگ بودن git) و ممیزی خودکار ترتیب قفل‌ها

**دقت ایجنت، بازگشت‌پذیری کامل (حتی برای دستورها)، سخت‌سازی امنیتی و سناریوهای اثبات سرتاسری:**

- **تذکر راستی‌آزمایی** — تغییر فایل بدون تست/ساخت موفق، یک راهنمای یک‌باره به حلقه‌ی ایجنت می‌افزاید تا دستور build/test را اجرا کند یا صادقانه بگوید نتوانسته تأیید کند
- **سقف توکن هر نوبت (واقعاً اعمال می‌شود)** — هشدار در ۸۰٪، توقف مودبانه بعد از دور جاری با حفظ امکان «ادامه»، شمارش مصرف زیرایجنت‌ها هم داخل سقف
- **نقطه‌ی بازگشت کل پروژه** — کارت خلاصه‌ی نوبت حالا «بازگردانی کل پروژه به قبل از این نوبت» دارد که با snapshot مخفیِ git حتی اثر جانبی دستورها را هم برمی‌گرداند؛ بازگردانی هیچ‌چیز حذف نمی‌کند (سبد زباله‌ی قابل‌بازگشت)
- **حالت ویرایش و مسیرهای محافظت‌شده** — «ویرایش خودکار» یا «بازبینی هر تغییر»؛ مسیرهای حساس (.env، فایل‌های تعریف ساخت، .git تودرتو حتی در submodule) حتی در حالت خودکار تأیید می‌خواهند
- **دروازه‌ی دستورات شله‌آگاه** — تجزیه‌گر واقعی CMD/POSIX + لیست‌سفید ساختاری: تلاش‌های معروف دورزدن (`&`، تغییرمسیر، `-exec`، `--output`، `^`، `%VAR%`) پرسش یا رد می‌شوند، هرگز اجرا
- **web_fetch فقط برای هر دامنه** — «همیشه اجازه» برای کل ابزار حذف شد؛ «همیشه برای همین دامنه» جایگزین است و قاعده‌های قدیمیِ سراسری به حالت پرسش برمی‌گردند
- **گسترش واقعیت‌های پروژه و کارها** — نوع پروژه و دستورهای راستی‌آزمایی پیشنهادی به پرامپت اضافه می‌شود و فهرست کارها از فشرده‌سازی کانتکست جان سالم به در می‌برد

## تازه‌های نسخه‌ی 1.7.1 — بازبینی کامل و سخت‌سازی

**بازبینی مستقل کامل پروژه (بک‌اند + فرانت‌اند + مصرف منابع + قابلیت اطمینان) با ۱۶ باگ رفع‌شده و ۹ تست رگرسیون جدید (مجموع ۳۶۹):**

- **رفع بحرانی مودال اجازه** — مودال تأیید دسترسی (اجرای دستور، خواندن فایل حساس، دریافت وب، ابزار MCP) به‌دلیل نبود کلاس `open` نامرئی و غیرقابل‌کلیک بود و همه‌ی درخواست‌ها پس از ۳ دقیقه خودکار «رد» می‌شدند؛ رفع و تست رگرسیون شد
- **MCP مقاوم‌تر** — چرخه‌ی بهبود بعد از کرش سرور که عملاً مرده بود فعال شد (حذف کلاینت مرده + backoff + راه‌اندازی مجدد خودکار)؛ نوشتن روی stdin سرورِ هنگ‌شده دیگر کل نوبت ایجنت را قفل نمی‌کند (نگهبان ۱۰ ثانیه‌ای + کشتن درخت فرایند)؛ آخرین پاسخ‌های سرورِ در حال خروج دیگر گم نمی‌شوند
- **قابلیت اطمینان** — فرمان‌های git با فرزندِ نگاه‌دارنده‌ی لوله دیگر بی‌نهایت بلاک نمی‌شوند (WaitDelay)؛ مودال خواندن فایل حساس با بستن برنامه فوراً لغو می‌شود؛ فایل قوانین عظیم زیر قفل کران‌دار خوانده می‌شود؛ دو رویداد از زیر قفل خارج شدند؛ shutdown منتظر پایان ذخیره‌ی آخرین نوبت می‌ماند
- **امنیت مرز داده** — فایل settings.json هم‌رسانی‌شده یا فایل گفتگوی کاشته‌شده دیگر نمی‌تواند اسکریپت به WebView تزریق کند: شناسه/رنگ Provider در بارگذاری پاک‌سازی و در ذخیره رد می‌شود و ایندکس گفتگو فقط شناسه‌های الگو‌دار می‌پذیرد
- **رفع باگ‌های فرانت‌اند** — پنل «برنامهٔ کار» هنگام تعویض گفتگو کهنه می‌ماند؛ ویرایشگر MCP بعد از ذخیره پیکربندی قدیمی را نشان می‌داد و ذخیره‌ی دوباره ویرایش را برمی‌گرداند؛ ذخیره‌ی نمونه‌ی نمایشی خالی دیگر تنظیم واقعی نمی‌نویسد

## تازه‌های نسخه‌ی 1.7.0

**برنامهٔ کار زنده، ویرایش چندگانه‌ی اتمیک، glob بر اساس زمان، دسترسی وب امن، پشتیبانی MCP و CI:**

- **برنامهٔ کار (todo_write)** — ایجنت برای کارهای چندمرحله‌ای فهرست کارهایش را با ابزار `todo_write` صریح نگه می‌دارد و شما آن را به‌صورت زنده در پنل «برنامهٔ کار» بالای جعبه‌ی پیام می‌بینید (در انتظار / در حال انجام / انجام شد + پیشرفت «۲ از ۵» با ارقام فارسی)؛ فهرست با گفتگو ذخیره می‌شود، در شاخه‌گیری کپی می‌شود و با باز کردن دوباره‌ی گفتگو برمی‌گردد
- **ویرایش چندگانه‌ی اتمیک (edit_file با edits)** — چند تغییر در یک فایل با آرایه‌ی `edits` (تا ۲۰ مورد) به‌ترتیب و «همه یا هیچ» اعمال می‌شود: اگر هر ویرایشی شکست بخورد هیچ‌چیز نوشته نمی‌شود و خطا می‌گوید ویرایش شمارهٔ چند و به چه علتی ناموفق بوده؛ یک بکاپ، یک Diff و یک تأیید برای کل مجموعه — شکل تک‌ویرایش مثل قبل کار می‌کند
- **glob بر اساس زمان تغییر** — نتایج `glob` جدیدترین فایل اول مرتب می‌شوند (تساوی با مسیر)؛ تا ۲۰٫۰۰۰ کاندید حین پیمایش جمع و پس از مرتب‌سازی ۵۰۰ نتیجه‌ی اول برگردانده می‌شود؛ فیلترهای gitignore و لغو با Stop مثل قبل
- **دریافت از وب با محافظت SSRF (web_fetch)** — ایجنت می‌تواند مستندات/صفحات خطا را با تأیید شما بخواند: فقط http/https و محتوای متنی؛ گارد اتصال IPِ «واقعاً resolve‌شده» را بازرسی می‌کند (حلقه‌ی محلی، محدوده‌های خصوصی/لینک-محلی شامل metadata ابر، CGNAT و…) و روی هر پرش redirect هم اعمال می‌شود؛ صفحات windows-1256/ISO-8859-6 درست decode می‌شوند و خروجی در پوشش `untrusted` می‌آید که محتوای آن فقط «داده» است، نه دستور

- **پرامپت آگاه از پلتفرم و CI** — پرامپت ایجنت حالا سیستم‌عامل و shell واقعی (CMD در ویندوز، sh در لینوکس/مک) را با راهنمای مناسب همان shell می‌گوید؛ بستن برنامه تأییدهای در انتظار را هم قطع می‌کند؛ گردش‌کار CI گیت‌هاب (تست windows با race detector + کامپایل لینوکس با GTK/WebKit + بیلد Wails) اضافه شد

  خودشان را با دعوت به افزودن دارند
- **حذف کامل گفتگو از همه‌جا** — با زدن دکمه‌ی حذف (یا «حذف همه»)، گفتگو به‌طور کامل پاک می‌شود:
  فایل روی دیسک، entry ایندکس و هشدارهای حجم. اگر گفتگو در حال پاسخ‌دهی باشد، ابتدا استریم
  متوقف و **منتظر خروج کامل گوروتین** می‌مانیم تا هیچ ذخیره‌ی دیرهنگام نتواند فایل را دوباره
  بسازد (رفع مسابقه‌ی «حذف فقط از رابط کاربری» — با تست رگرسیون اختصاصی پوشش داده شده)
- **دکمه‌ی حمایت از پروژه** — دکمه‌ی زیبا با قلب ضربان‌دار در صفحه‌ی اصلی که صفحه‌ی
  `coffeebede.com/khademdev` را در مرورگر پیش‌فرض باز می‌کند
- اعتبارسنجی فرم Provider کامل شد (حداقل یک مدل الزامی است)؛ TestProvider بدون مدل هم دیگر
  خطای گمراه‌کننده نمی‌دهد
- تست‌های رگرسیون جدید: مهاجرت تنظیمات، حذف آخرین Provider، حذف کامل گفتگو (فایل/ایندکس/لیست)،
  حذف گفتگو در حین استریم (با سرور SSE آزمایشی) — کل مجموعه سبز، همراه با race detector

## ویژگی‌ها

### حالت ایجنت (شبیه OpenCode)
- **سوییچ «حالت ایجنت» در سایدبار** — وقتی فعال باشد، مدل به مجموعه‌ای از ابزارهای سیستم دسترسی پیدا
  می‌کند و می‌تواند در چند مرحله‌ی پشت‌سرهم روی پروژه کار کند:
  `list_dir`، `read_file`، `write_file`، `edit_file` (جایگزینی دقیق یا چندگانه‌ی اتمیک با آرایه‌ی `edits`
  با کنترل یکتایی و تطبیق‌گر مقاوم CRLF/فاصله/تورفتگی)، `move_path`، `delete_path`، `create_dir`، `search_files` (جستجوی متن/regex در
  کل پروژه؛ با فیلتر `include` روی مسیر/نوع فایل، `context` برای خطوط اطراف و `case_sensitive` برای تطبیق دقیق حروف — پیش‌فرض غیرحساس)، `glob` (یافتن فایل با الگو؛ جدیدترین تغییر اول) و `run_command`
  (اجرای دستور در پوشه‌ی پروژه با اجازه‌ی صریح کاربر؛ با `background:true` فرایند پس‌زمینه
  شروع می‌شود و شناسه برمی‌گردد — سپس `process_output` لاگ تازه را می‌خواند، `process_stop`
  کل درخت فرایند را تمیز می‌کشد و `process_list` وضعیت را نشان می‌دهد) + ابزارهای `git_*` (وضعیت/diff/تاریخ/کامیت‌ها)،
  **`task` (زیرایجنت فقط‌خواندنی با کانتکست تازه برای زیرکارهای اکتشافی)**،
  **`todo_write` (برنامهٔ کار زنده)**، **`web_fetch` (دریافت امن مستندات/صفحات از وب)** و
  **`find_symbol` و `find_references` (ایندکس نمادها: نماد کجاست تعریف شده و کجا استفاده می‌شود — تطبیق مرز-کلمه‌ای)**، **ابزارهای `mcp_*` (سرورهای MCP خارجی)**
- **زیرایجنت (task)** — برای جستجو/تحلیل‌های گسترده، ایجنت می‌تواند کار را به یک زیرایجنت فقط‌خواندنی
  بسپارد که با کانتکست تازه کار می‌کند و گزارش ساختارمند برمی‌گرداند؛ سقف دورها قابل تنظیم است
  (تب «مدل و رفتار»)، هر واگذاری با مودال اجازه تأیید می‌شود و فایل‌های حساس داخلش خوانده نمی‌شوند
- **حلقه‌ی ایجنت واقعی** — مدل فراخوانی ابزار می‌فرستد، نتیجه به او برگردانده می‌شود و تا رسیدن به پاسخ
  نهایی ادامه می‌یابد (حداکثر ۲۵ دور برای جلوگیری از حلقه‌ی بی‌پایان)
- **کارت‌های فعالیت ابزار** — هر خواندن/نوشتن/اجرا به‌صورت کارت مستقل با نام ابزار، خلاصه‌ی آرگومان،
  وضعیت موفق/خطا، زمان اجرا و نتیجه‌ی قابل باز/بسته شدن نمایش داده می‌شود
- **نوار «گزارش زنده»** — سطح همیشه‌روی کار ایجنت: هر عملیات یک جمله‌ی فارسی
  («در حال خواندن `agent.go`»، «فایل `x` ویرایش شد»، «حذف `y` ناموفق بود — دلیل») با نشانگر
  در حال انجام/موفق/ناموفق و زمان اجرا؛ در پایان نوبت خودکار جمع می‌شود و شمارنده‌ی «۱۲ عملیات»
  می‌ماند. هر خط، برچسب وظیفه‌ی متناطر («وظیفهٔ ۲ از ۵») را از پنل «برنامهٔ کار» دارد و
  `todo_write` به یک خط جمع‌شده («برنامهٔ کار به‌روزرسانی شد — ۲ از ۵») تبدیل می‌شود تا فهرست
  کارها دو بار نمایش داده نشود. روشن/خاموش‌کردنش در تب «مدل و رفتار» است و ذخیره می‌شود
- **پنل «برنامهٔ کار»** — چک‌لیست `todo_write` با پیشرفت «۲ از ۵»؛ پیش‌فرض جمع‌شده است تا با
  گزارش زنده اشتباه نشود و فقط وقتی چک‌لیستی وجود دارد ظاهر می‌گردد
- **راستی‌آزمایی پوششی** — تذکر پایان نوبت فقط نمی‌پرسد «تستی اجرا شد؟»؛ دایرکتوری‌های
  تغییرکرده را می‌گوید، «فقط build» را از «تست» جدا می‌کند و یک دستور تست هدفمند پیشنهاد
  می‌دهد (مثل `go test ./pkg/a/...`) تا اثبات تغییر، به همان بخشی بچسبد که عوض شده است
- **کش پرامپت (اختیاری)** — با روشن‌کردن `promptCache` در تنظیمات، بلوک ثابت پرامپت
  (system + ابزارها) برای سرویس‌دهنده‌های سازگار با `cache_control` نشانه‌گذاری می‌شود؛
  اگر ارائه‌دهنده رد کند، یک‌بار بدون آن تلاش می‌شود و تا restart فراموش می‌شود
- **امنیت مسیر** — همه‌ی ابزارهای فایل به‌شدت داخل «پوشه‌ی کاری» محدود می‌شوند (خروج با `..` یا مسیر
  مطلق بیرون از پروژه مسدود است) و اجرای دستور فقط با سوییچ «اجازه اجرای دستور» انجام می‌شود
- **ذخیره‌ی تدریجی** — هر دور ابزار بلافاصله روی دیسک ذخیره می‌شود؛ بستن برنامه در میانه‌ی کار،
  فعالیت انجام‌شده را از بین نمی‌برد
- **سازگاری هوشمند** — اگر مدل/سرویسِ انتخابی از فراخوانی ابزار پشتیبانی نکند، به‌صورت خودکار یک‌بار
  بدون ابزار تلاش می‌شود و به کاربر اطلاع داده می‌شود

### چت
- **صفحه‌ی چت با حالت خالی زیبا** — آیکون تراشه‌ی AI درخشان، پیام خوش‌آمد، چیپ‌های پیشنهاد سریع
  (نوشتن قطعه کد، بررسی پروژه با ایجنت، ایده‌پردازی، اشکال‌زدایی، بازبینی امنیت کد)
- **مکالمه‌ی کامل** — حباب کاربر سمت راست (تیره‌تر)، پاسخ AI سمت چپ با رندر کامل **Markdown**،
  جدول، نقل‌قول و **بلوک کد با شماره‌ی خط، هایلایت سینتکس و دکمه‌ی کپی**
- **پاسخ استریمی** — نشانگر «در حال فکر کردن…»، کرسر تایپ زنده، دکمه‌ی «توقف» (هم در composer و
  هم کنار پاسخ) + «تولید دوباره» واقعی روی آخرین پاسخ
- **سایدبار راست** — دکمه‌ی «گفتگوی تازه»، جستجوی گفتگوها، لیست گفتگوها با تاریخ نسبی فارسی
  («امروز 10:42»، «۲ روز پیش»)، نشان «جدید»، حذف تکی و «حذف همه» با تأیید
- **مودال تنظیمات با ۳ تب**:
  - **اتصال** — انتخاب Provider (با آیکون)، مدل (با پیشنهاد خودکار)، کلید API با نمایش/مخفی،
    تست اتصال و ذخیره‌ی رمزنگاری‌شده‌ی کلید (AES-GCM)
  - **Provider ها** — افزودن/ویرایش/حذف سرویس‌دهنده‌های سازگار با API نوع OpenAI؛ فرم Provider فقط
    **نام سرویس و کلید API** را می‌پرسد و آدرس/مدل‌ها/کانتکست را خودکار از سرویس‌دهنده کشف می‌کند؛
    بعد از ذخیره، Provider تازه فعال و اولین مدل چت خودکار انتخاب می‌شود
    (بدون Provider پیش‌فرض — کاربر خودش تعریف می‌کند)
  - **پوشه‌ی کاری (مسیر پروژه)** — **تایپ مستقیم مسیر** (مثلاً `C:\Projects\MyApp`) یا انتخاب با
    دیالوگ سیستم‌عامل؛ اگر مسیر وجود نداشته باشد هنگام ذخیره **به‌صورت خودکار ساخته می‌شود** و
    خطاها همراه با علت واقعی نمایش داده می‌شوند + سوییچ «اجازه اجرای دستور»
- **سوییچ «حالت ایجنت» در چت‌باکس** — هماهنگ با تنظیمات؛ «اجرا دستور» فقط در تنظیمات (تب پوشه‌ی کاری) است و اجرای دستور فقط در
  پوشه‌ی کاری و فقط با اجازه انجام می‌شود
- **نشانگر مصرف توکن** — پیلِ «کانتکست» در نوار بالا: دایرهٔ درصد + کسر خوانا
  («۱۲هزار از ۲۰۰هزار») و برچسب مشخص که نشان می‌دهد عدد مربوط به «پنجرهٔ کانتکست همین
  گفتگو» است، نه سهمیهٔ حساب. کلیک روی آن پاپ‌اور توضیح فارسی باز می‌کند: عدد کانتکست
  (دقیق/تخمینی)، مصرف تجمعی Provider و مدل فعال، تاریخ آخرین صفر کردن، و دکمهٔ
  دو مرحله‌ای «شمارنده را صفر کن (پس از شارژ سرویس)». مصرف تجمعی روی دیسک ذخیره
  می‌شود و با بستن برنامه یا قطع/وصل اتصال صفر نمی‌شود
- **حسابداری مصرف** — هر دور فقط یک‌بار ثبت می‌شود (جمع prompt+completion همان دور)؛
  اعداد به تفکیک Provider و مدل، و مصرف هر گفتگو جدا ذخیره می‌شود
- **انتخابگر مدل** — پاپ‌اور گروه‌بندی‌شده بر اساس Provider (با جستجو) از دکمه‌ی مدل در چت‌باکس.
  «محیط پاسخ‌دهی» از رابط برداشته شد؛ رفتار با حالت چت/ایجنت و «دستور سیستمی» در تنظیمات تعیین می‌شود
- **مدیریت BiDi** — کدها، مسیر فایل‌ها و URLها همیشه با `unicode-bidi: isolate` و جهت LTR
  نمایش داده می‌شوند و متن فارسی راست‌چین می‌ماند

## مدل امنیتی / Security model

**فارسی — صادقانه و بدون اغراق:**

- **ابزارهای فایل فقط داخل پوشه‌ی کاری** — همه‌ی مسیرهای داده‌شده به ابزارها از ریشه‌ی پروژه حل می‌شوند؛ خروج با `..` یا مسیر مطلق/فرار مسدود است. فایل‌های حساس (`.env*`، `*.pem` و…) و مسیرهای محافظت‌شده (.git حتی تودرتو، فایل‌های تعریف ساخت مثل `package.json`) حتی در «ویرایش خودکار» مودال تأیید می‌گیرند.
- **دستورها گیت‌دار هستند و سندباکس ویندوزی دارند** — اجرای دستور از سه لایه می‌گذرد: تجزیه‌گر شله‌آگاه (عدم‌قطعیت = پرسش)، لیست‌سفید ساختاری (git/go/npm با پرچم صریح) و بررسی توکن حساس/مسیر محافظت‌شده. در ویندوز می‌توانید از تنظیمات → پوشه، «سندباکس اجرای دستور» را روشن کنید: هر دستور داخل یک **AppContainer واقعی** (SID اختصاصی، ACL هدفمند، Job Object) اجرا می‌شود — خواندن/نوشتن فقط در پوشه‌ی کاری و خانه‌ی موقت ایزوله، پروفایل کاربر ممنوع و شبکه با کلید «اجازه‌ی شبکه». اگر روشن باشد و راه‌اندازی شکست بخورد، دستور **اجرا نمی‌شود** (fail-closed). **پیش‌فرض روشن است**؛ ابزارهای نیازمند NUL (go/git) با ثبت خودکار یک Scheduled Task کاربری (و fallback به Startup) و اجرای فوری آن کار می‌کنند (جزئیات در «محدودیت شناخته‌شده»). روی لینوکس/مک جداسازی سیستمی وجود ندارد؛ UI این را صادقانه نشان می‌دهد.
- **دستورهای تست/ساختِ خودکارِ اجازه‌ی بدون پرسش کد اجرا می‌کنند** — `go test`، `npm test` و مانند آن‌ها بدون مودال اجرا می‌شوند چون بی‌خطر به نظر می‌رسند؛ اما آن‌ها همان کدی را اجرا می‌کنند که ایجنت چند لحظه قبل نوشته است. **شبکه‌ی ایمنی واقعی، بازبینی پایان نوبت است**: کارت «خلاصه‌ی واقعی این نوبت» را بخوانید و پیش‌نمایش Diff مسیرهای محافظت‌شده را تأیید کنید. دکمه‌های «برگرداندن تغییرات» در این نسخه از رابط کاربری حذف شده‌اند؛ روی شاخه‌ی git کار کنید و پیش از نوبت‌های سنگین وضعیت را کامیت کنید.
- **حالت‌های ویرایش** — «بازبینی هر تغییر» مودال Diff برای هر نوشتن می‌دهد؛ «ویرایش خودکار» فقط مسیرهای محافظت‌شده و حذف سنگین را می‌پرسد و بقیه را در خلاصه‌ی نوبت گزارش می‌کند.
- **نظم راستی‌آزمایی و سقف توکن** — ایجنت بعد از تغییر فایل بدون تست/ساختِ موفق یک تذکر یک‌باره می‌گیرد؛ «سقف توکن هر نوبت» مصرف همه‌ی دورها + زیرایجنت‌ها را می‌سنجد و نوبت را مودبانه متوقف می‌کند.
- **اعتماد به محتوای بیرونی** — خروجی `web_fetch` و ابزارهای MCP در پوشش `untrusted` به مدل می‌رسد (فقط داده، نه دستور)؛ گارد SSRF اتصال را در هر پرش بازرسی می‌کند؛ اجازه‌ی web_fetch فقط برای هر دامنه ذخیره می‌شود (هرگز برای کل ابزار). سرورهای MCP فرایند قابل‌اعتمادِ شما هستند اما با محیط حداقلی بالا می‌آیند (بدون کلیدهای API برنامه) و هر فراخوانی ابزارشان مودال اجازه دارد.
- **داده‌ها روی دستگاه شما** — کلید API با AES-GCM و کلید میزبان در Keyring سیستم‌عامل رمز می‌شود؛ محیطی متغیرهای MCP رمزنگاری‌شده ذخیره و در UI فقط ماسک می‌شوند؛ هیچ چیزی جز آدرس Provider به بیرون رفت نمی‌کند (و آن هم فقط به سرویس‌دهنده‌ی خودتان).
- **گردش‌کار پیشنهادی** — روی یک شاخه‌ی git کار کنید، حالت ویرایش را آگاهانه انتخاب کنید، در پایان هر نوبت کارت خلاصه را بخوانید و در صورت شک، تغییرات را با git (diff/checkout) بازبینی کنید.
- **پایداری (1.8.1)** — خطای داخلی برنامه را نمی‌کشد (مهار panic در همه‌ی گوروتین‌ها و متدهای بایند‌شده)، سکون سرویس‌دهنده با نگهبان ۱۸۰ ثانیه‌ای تمام می‌شود، فایل گفتگو/`changes.json` با `.bak` و نجات پیام‌های سالم بازیابی می‌شوند و بازگردانی چک‌پوینت با `EvalSymlinks`/رد reparse از نوشتن بیرونِ پروژه جلوگیری می‌کند. این‌ها تضمین‌های پایداری‌اند، نه جداسازی سیستمی؛ سندباکس واقعی همان بند دوم است.
- **محدودیت شناخته‌شده‌ی سندباکس** — در AppContainer دستورهای داخلی `cmd` و نوشتن در پوشه‌ی کاری کار می‌کنند و دسترسی بیرون از پوشه واقعاً بسته است (تست‌های `TestSandbox*`). دستورهای ساده مستقیم (بدون cmd) اجرا می‌شوند و پس از اجرای یک‌باره‌ی `scripts/grant-sandbox-nul.ps1` (که ACE دستگاه NUL را برای SID سندباکس اضافه می‌کند) این‌ها داخل AppContainer تأیید شده‌اند: `go version`، `go vet ./...`، `go test ./...` و `git --version`. بدون اجرای آن اسکریپت، ابزارهای نیازمند NUL با `open NUL: Access is denied` متوقف می‌شوند. DACL دستگاه NUL در حافظه‌ی کرنل است و با هر ری‌استارت بازنشانی می‌شود؛ خود برنامه یک Scheduled Task در سطح کاربر ثبت می‌کند (اگر ساخت آن مجاز نبود، پوشه‌ی Startup fallback است) و هنگام شروع یک‌بار اجرا می‌کند. این Task به مسیر فایل اجرایی فعلی گره خورده است؛ اگر MyAI حذف یا جابه‌جا شود، اجرای بعدی‌اش خودش را همراه اسکریپت‌ها و fallback پاک می‌کند. `dir` — هم به‌تنهایی و هم داخل زنجیره‌های `&&`/`||`/`&` — با یک لیست‌کننده‌ی داخلی که فقط به پوشه‌ی کاری محدود است اجرا می‌شود (`vol` و اطلاعات volume همچنان در دسترس نیست)؛ دستورهای مرکب (`&&`، `||`، `|`، تغییرمسیر) از cmd اجرا می‌شوند و حالا با `CREATE_NO_WINDOW` فرزندان خارجی (git/go/node) هندل‌های std معتبر می‌گیرند. سازگاری git: runtime‌ی MSYS نمی‌تواند شیء نام‌دارش را در AppContainer بسازد (NtCreateDirectoryObject با 0xC0000022 شکست می‌خورد)؛ بنابراین دستورهای git — و ترکیب‌های صرفاً git — آگاهانه و مستند خارج از AppContainer ولی همچنان تحت دروازه‌ی دسترسی و مودال اجازه اجرا می‌شوند و این استثنا یک‌بار در «لاگ خطاها» ثبت می‌شود. همین استثنا در تنظیمات → پوشه، زیر «اجازه‌ی شبکه در سندباکس»، به‌صورت یک یادداشت به کاربر نشان داده می‌شود. هر دستور دیگر (go/node/npm/…) سندباکس‌شده می‌ماند.

**English — stated honestly, without overstatement:**

- **File tools are confined to the workspace.** Every model-supplied path is resolved against the workspace root; `..`, absolute and escape paths are rejected. Sensitive files (`.env*`, `*.pem`, …) and protected paths (`.git` including nested submodule ones, build-definition files like `package.json`) always ask, even in the "auto" edit mode.
- **Commands are gated, with an opt-in Windows sandbox.** Command execution passes a shell-aware parser (uncertainty → ask), a structural allow-list (git/go/npm with explicit flags) and sensitive-token/protected-path checks. In Settings → Folder you can enable the command sandbox: each command then runs inside a real **AppContainer** (dedicated SID, targeted ACLs, Job Object) — read/write only in the workspace and an isolated temp home, the user profile is inaccessible, and network access follows the "allow network" switch. If it is on and cannot start, the command is **not run** (fail-closed). Turning it off in Settings removes the ACEs it added for its sandbox SID (tracked in a local grant cache), so no extra access is left behind. It is **on by default** on Windows; the NUL-device grant is registered as a per-user scheduled task (Startup-folder fallback) and applied at launch, so go/git work inside the sandbox (see the known limitation for `dir`). On Linux the same switch uses **bubblewrap** (bwrap): a private user/pid/net/ipc/uts namespace, the whole filesystem read-only except the workspace and an isolated temporary home, `/tmp` as a private tmpfs, a cleared environment with an allowlist (no API keys) and no capabilities; network follows the "allow network" switch. If bwrap is not installed the command is **not run** and the error says so (fail-closed). MCP servers use the same bwrap isolation with real stdio pipes. macOS has no OS-level isolation yet and uses the gated path; the UI states this honestly.
- **Auto-allowed test/build commands execute code the agent may have just written.** `go test`, `npm test` and similar are auto-allowed because they look harmless — yet they run whatever the agent just wrote. The real safety net is the end-of-turn review: read the "real turn summary" card and confirm the Diff preview for protected paths. The revert/restore buttons were removed from the UI in this release; work on a git branch and commit before heavy turns.
- **Edit modes** — "review each change" shows a diff modal for every write; "auto" only asks for protected paths and heavy deletes and reports everything else in the turn summary.
- **Verification discipline & token cap** — a final answer without a successful build/test since the last file change triggers a one-time verification nudge; «سقف توکن هر نوبت» (max tokens per turn) counts all rounds plus sub-agents and stops the turn gracefully.
- **Untrusted content** — `web_fetch` and MCP results reach the model inside an `untrusted` envelope (data, never instructions); the SSRF guard re-checks every redirect hop; web_fetch and web_search permissions are stored **per host** only — never tool-wide. web_search (DuckDuckGo HTML, no API key) returns titles, URLs and snippets inside a `<search_results untrusted="true">` envelope with the same SSRF guard, and every source carries its full URL so the model can cite it. MCP servers are your trusted local processes but run with a minimal environment (never the app's API keys) and every tool call asks.
- **Your data stays on your machine** — API keys are AES-GCM encrypted with an OS-keyring master key; MCP env vars are encrypted and masked in the UI; nothing leaves the device except your own provider requests.
- **Recommended workflow** — work on a git branch, choose the edit mode deliberately, read the turn summary card after every turn, and when in doubt try "revert this turn" first, then "restore the whole project".
- **Stability (1.8.1)** — an internal error no longer kills the app (panic recovery in every goroutine and bound method), a silently stalled provider stream ends after a 120 s idle watchdog, conversation/`changes.json` files get `.bak` + salvage recovery with a Persian notice, and checkpoint restore refuses symlinked/junction parents (real-path resolution) and streams file comparisons so memory stays flat. These are resilience guarantees, not OS-level isolation; the real sandbox is the AppContainer bullet above.
- **Known sandbox limitations** — inside AppContainer, `cmd` built-ins such as `echo`/`type`, `dir` (served by a built-in lister confined to the workspace, including inside `&&`/`||`/`&` chains, and `dir > file` / `dir >> file` redirects that can only write inside the workspace), direct executables and writes in the workspace work, and access outside the workspace is genuinely blocked (see `TestSandbox*`). `vol`/volume information stays unavailable because it needs access to the drive root. Composite commands (`&&`, `||`, `|`, redirections) run through `cmd`, which now passes valid std handles to external children (`CREATE_NO_WINDOW` instead of `DETACHED_PROCESS`). Git compatibility: the MSYS runtime cannot create its named shared-memory object inside an AppContainer (`NtCreateDirectoryObject` fails with 0xC0000022), so git commands — and pure-git composites — run outside AppContainer while still passing the permission gate; the exemption is logged once in the error log. A lone read-only `cygpath` call is exempt for the same reason (path conversion works with the sandbox on), while `cygpath` with a redirect, a pipe or any second command stays sandboxed. The exemption is also shown to the user as a note under Settings → Folder → “Allow network in sandbox”. Every other command (go/node/npm/…) stays sandboxed. The app registers a per-user scheduled task (falling back to the Startup folder) and runs the grant at launch; the NUL device ACL resets on reboot, so that entry keeps toolchains working. The task is pinned to the current executable path: once MyAI is removed, its next run deletes the task, both scripts and the Startup fallback.

## ساخت و اجرا

```bash
cd myai

# حالت توسعه (hot-reload)
wails dev

# ساخت باینری نهایی برای سیستم خودتان
wails build

# کامپایل متقاطع برای ویندوز از لینوکس/مک (بدون نیاز به MinGW — خالص Go)
wails build -platform windows/amd64 -skipbindings -ldflags "-s -w -X main.version=1.3.0"

# خروجی این‌جا ساخته می‌شود:
#   ویندوز: build/bin/MyAI.exe
#   مک:     build/bin/MyAI.app
#   لینوکس: build/bin/MyAI
```

> نکته‌ی مهم: خروجی ویندوز (`MyAI.exe`) کاملاً خالص Go است و برای کامپایل متقاطع به ابزار
> اضافه‌ای نیاز ندارد. خروجی لینوکس به بسته‌های توسعه‌ی `libwebkit2gtk-4.0-dev` روی ماشین
> build نیاز دارد (بینه‌ی لینوکس باید روی همان لینوکس ساخته شود).

> پوشه‌ی `build/bin` محل خروجی کامپایل شماست؛ بینه‌ی آماده‌ی ویندوز در همین بسته تحویل شده است.

## معماری ارتباط فرانت‌اند و بک‌اند

- متدهای `App` (فایل‌های Go) به‌صورت خودکار توسط Wails به `window.go.main.App` بایند می‌شوند
  (`SettingsView`، `SendMessage`، `SaveConnection`، `SaveProvider`، `SelectFolder`، …)
- استریم پاسخ با **رویدادهای Wails** به فرانت‌اند می‌رسد:
  - `chat:start` — شروع پاسخ (همراه گفتگوی تازه‌ساخته‌شده)
  - `chat:delta` — هر تکه‌ی متن
  - `chat:tool` / `chat:tool_result` — شروع/پایان هر فراخوانی ابزار ایجنت
  - `chat:notice` — اطلاعیه‌ها (مثلاً پشتیبانی‌نشدن ابزار توسط مدل)
  - `chat:done` — پایان (با مصرف توکن)
  - `chat:error` — خطا
- هر API سازگار با OpenAI (`/chat/completions`) پشتیبانی می‌شود؛ حالت ایجنت از **فراخوانی تابع
  (Function Calling)** استاندارد OpenAI استفاده می‌کند، پس مدل باید ابزار را پشتیبانی کند
  (gpt-4o، llama-3.3، qwen2.5 و…). در صورت پشتیبانی‌نکردن، برنامه به‌صورت خودکار به چت معمولی برمی‌گردد.
  علاوه بر این، هر سرویسی (OpenRouter، Together، سرویس‌های ایرانی و…) از تب
  «Provider ها» قابل افزودن است.

## MCP داخل سندباکس

سرورهای MCP هم مثل دستورهای شل داخل AppContainer اجرا می‌شوند: SID اختصاصی،
ACL فقط روی پوشه‌ی کاری و خانه‌ی ایزوله، Job Object با KILL_ON_JOB_CLOSE،
محیط حداقلی و شبکه فقط وقتی «اجازه‌ی شبکه» روشن باشد. stdin/stdout/stderr سه
pipe واقعی هستند، پس JSON-RPC خط‌به‌خط و ابزارهای سرور با سندباکس روشن هم کار
می‌کنند. اگر آماده‌سازی سندباکس شکست بخورد، سرور اجرا نمی‌شود (fail-closed) و
خطا در وضعیت همان سرور نمایش داده می‌شود؛ هیچ‌وقت بیرون از سندباکس بالا نمی‌آید.
